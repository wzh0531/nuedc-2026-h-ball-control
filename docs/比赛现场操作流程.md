# 2026 H题比赛现场操作流程

## 1. 最终软件版本

### MaixCAM Pro

比赛使用目录：

```text
firmware/maixcam
```

正式入口：`main.py`。

- `main.py`：固定热点、WebRTC、钢球识别、可选零点和UART输出；
- `calibrate.py`：只在赛前机械位置变化后重新标定，比赛测试时不要运行；
- `calibration_config.py`：保存最终安装状态下的轴线和厘米标定；
- `webrtc_record_server.py`：iPad录像、回放、保存和零点操作页；
- `model_310817.mud/.cvimodel`：正式钢球检测模型。

当前代码启动版本名为：

```text
webrtc_ball_hdemo_uart_310817_roi_selected_zero_v1
```

固定网络参数：

```text
SSID：MaixBall-AP
密码：在未提交的`firmware/maixcam/local_config.py`中配置
MaixCAM IP：192.168.66.1
录像和零点页面：http://192.168.66.1:8080/
只观看页面：http://192.168.66.1:8000/
```

UART保持固定5字节协议：

```text
UART1，115200 8N1
A19=TX，A18=RX
7B tracking dx_hi dx_lo 7D
```

### MSPM0G3507

比赛使用Keil工程：

```text
firmware/mspm0/project/mdk/SeekFree_MSPM0G3507_Device_Library.uvprojx
```

烧录前必须用Keil全量重编译，确认0 error、0 warning，并确认生成时间为本次比赛固件。

## 2. 按键与显示

| 操作 | 功能 |
|---|---|
| KEY1短按 | READY/FINISHED下选择上一个任务，任务2向前循环到任务6 |
| KEY2短按 | READY/FINISHED下选择下一个任务，任务2→3→4→5→6 |
| KEY3短按 | READY时启动当前任务；任务3完成后在FINISHED短按可复位回READY |
| KEY4按下 | 急停并进入FAULT；不用于正常结束计时 |
| KEY4重新长按约1秒 | 松开急停键并排除故障后，将FAULT/FINISHED复位到READY |

OLED关键字段：

- `TASK`：当前选择的任务号；
- `STATE`：必须确认`READY/RUN/BRAKE/FINISH/FAULT`；
- `TIME`：从KEY3启动开始的当前时间；
- `RES`：按赛题口径锁存的有效成绩时间；
- `FAULT`：非零时不得继续测试。

任务2～6正常运行后都自动结束，不要用KEY3人为结束计时。任务3运行中再次按KEY3仅保留为提前结束的调试备用操作。

## 3. 每次上电的统一流程

### 3.1 机械和电气检查

1. 确认摆杆、水管、相机和MaixCAM位置没有松动；机械位置变化后旧标定失效。
2. 确认钢球、凹槽和轮胎无杂物，机构运动范围内没有线束干涉。
3. 确认MaixCAM UART与MSPM0交叉连接并共地。
4. 确认F32C地址为2，摆杆处于机械安全位置。
5. 确认电池电量、iPad电量和iPad剩余存储空间充足。
6. 确认KEY4没有被压住。

### 3.2 启动MaixCAM

1. 停止其他占用相机的JPEG、RTSP或测试程序。
2. 从最终目录运行`main.py`，不要误运行`calibrate.py`。
3. 检查日志至少包含：

```text
Program: webrtc_ball_hdemo_uart_310817_roi_selected_zero_v1
WiFi AP: ... 192.168.66.1
WebRTC: 1280x720 ... 30 fps
AI channel: 640x360 ... 30 fps
```

4. 连续观察数秒`STATS`：

```text
inference_fps >= 20
tracking=1
detected数量应接近总推理数量
uart=7B 01 .. .. 7D
```

5. 同时确认没有持续出现UART短写、UART异常或相机读取`[WARN]`；如果
   `tracking=0`、帧率低于20或警告持续出现，不得开始比赛。

### 3.3 启动MSPM0

1. 上电时保持整车静止，等待IMU标定完成。
2. OLED从`CAL`变为`READY`前不要搬动车辆。
3. 在调试串口发送一次`BALL`，确认：

```text
init=1
track=1
frame计数持续增加
txfail=0
```

4. 确认小球偏差方向正确：球向物理正方向移动时，Maix偏差符号和摆杆纠偏方向必须正确。

### 3.4 连接iPad并做录像预检

1. 连接`MaixBall-AP`，使用`local_config.py`中配置的密码；显示“无互联网”属于正常现象。
2. 关闭VPN、自动切换其他Wi-Fi和自动锁屏。
3. Safari打开`http://192.168.66.1:8080/`。
4. 等到页面显示WebRTC已连接，确认完整画面、方向和分辨率正常。
5. 录制一次10～30秒短视频，停止、回放并保存，确认文件能重新打开。

## 4. 每轮比赛的通用步骤

1. 上一轮若处于`FAULT`，先排除故障，松开KEY4，再重新长按KEY4复位。
2. 上一轮若处于`FINISHED`且需要进入第三问，可短按KEY3或长按KEY4复位到`READY`。
3. 用KEY1/KEY2选择题号，以OLED的`TASK`为准。
4. 按对应题目的要求设置MaixCAM零点。
5. 把车辆测试点对准起点，灰度阵列处于正确循迹位置。
6. 确认OLED为`READY`、`FAULT=0`；除第2问外，钢球应已在对应零点稳定。
7. iPad点击“开始录像”，确认录像计时已经开始。
8. 向裁判确认准备完毕后，短按KEY3启动。
9. 运行中不得再设置零点、修改PID或遥控车辆。
10. 正常完成后确认OLED进入`FINISH`并记录`RES`。
11. iPad点击“停止”，立即回放，再点击“保存/分享”。
12. 每一问单独保存一段视频，文件名建议包含题号、轮次和成绩。

## 5. 第2问操作：小车一圈后停在A点

### 测试前

1. 选择`TASK 2`。
2. 本问与钢球无关，可以不放钢球；软件会忽略球位置PID与加速度前馈，持续命令F32C保持`0°`水平位。
3. F32C上电后会先回到电机内部保存的单圈绝对`0°`，再将该位置清为多圈`0°`；首次必须无球确认这个保存零点确实对应摆杆水平。
4. 将车体指定测试点准确放到A点，确认出发方向正确。
5. 确认灰度阵列能看到赛道黑线，车轮没有压偏。

### 启动和结束

1. iPad开始录像。
2. 短按KEY3，计时自动从0开始。
3. 小车自动循迹一圈、识别A线、预减速并停车。
4. 不要在运行中再次按KEY3。
5. OLED进入`FINISH`后记录`RES`和停车偏差。

### 注意事项

- 任务2要求停车精度，起点位置和车体测试点定义每次必须一致；
- 普通弯道可能出现3路黑，程序使用里程、时间和连续4路黑共同确认A点；
- 如果越过A点仍未自动停车，优先按KEY4确保安全；调试场地可用UART `STOP`平滑停车，但正式测试不应人工干预；
- 每次至少记录用时、停车前后偏差和是否误识别A点；本问不记录小球指标。

## 6. 第3问操作：静止状态中心到+5 cm再到-5 cm

### 测试前

1. Maix页面点击“恢复中心零点”，确认零点为物理中心`0.00 cm`。
2. 选择`TASK 3`。
3. 必须确认OLED状态为`READY`，不能停留在`FINISH`。
4. 在`READY`状态下目标严格为中心`0 cm`，等待钢球在中心稳定；此时不得提前向`+5 cm`移动。
5. 若刚完成上一轮处于`FINISH`，短按KEY3或长按KEY4复位到`READY`。

### 启动和结束

1. iPad开始录像，画面应同时看到钢球和位置参照。
2. 短按KEY3：自动开始计时，钢球目标由中心切换到`+5 cm`。
3. 底盘在整个过程中保持不动。
4. 程序检测钢球在`+5 cm`附近稳定后，自动把目标切换到`-5 cm`。
5. 钢球在`-5 cm`附近稳定后，系统自动进入`FINISH`并把当前`TIME`锁存为`RES`，无需第二次按键。

### 注意事项

- KEY4是急停，不是第三问正常停止键；
- 第一次KEY3负责启动，正常完成由程序自动停止；运行中第二次KEY3只用于调试时提前结束；
- 不要用Maix“设置当前位置为零点”代替MSPM0的`+5/-5 cm`时序；
- 若运动方向相反，停止测试，只调整滚球方向参数，不能通过交换`+5/-5`评分定义规避；
- 记录总时间、两端稳态误差、最大超调和是否触及机械限位。

### 静止串口调参（不启动底盘）

1. 底盘驱动电源可断开，但MSPM0、MaixCAM和F32C必须正常供电并共地。
2. 选择`TASK 3`并保持`READY`，不要按KEY3或发送`START`。
3. 先发送`BALL FF 0`做无前馈基线；当前默认起点为`BALL PID 0.40 0.50 0`和`BALL LIMIT 2 8 15`。
4. 破静摩擦默认为`BALL STICK 3.2 0.35 0.25`、`BALL BOOST 7 300 4`和`BALL SHAKE 2.4 120 120`：卡住300 ms后正向轻推120 ms，随即反向2.4°制动120 ms，再冷却500 ms。
5. 使用`BALL TARGET 0`、`BALL TARGET 5`、`BALL TARGET -5`切换静止目标；用`BALL`重点查看`stick_phase`（0/空闲、1/轻推、2/制动）、`stick_cooldown`、位置和实际角度。若连续穿越中心3次，立即发送`TASK 2`回水平。
6. 调试结束发送`BALL TARGET OFF`，再用`BALL FF 1.0`和`BALL FFLEAD 150`恢复当前前馈初值。稳态按`atan(a/g)`计算，起步/刹车建立加速度时加入150 ms jerk前瞻；参数仅保存在RAM，复位后恢复默认值。

## 7. 第4问操作：A到B并保持钢球中心

### 测试前

1. 选择`TASK 4`。
2. 点击“恢复中心零点”，确认零点为`0.00 cm`。
3. 等待钢球稳定在中心。
4. 将车体指定测试点对准A点，确认前进方向和灰度位置。

### 启动和结束

1. iPad开始录像。
2. 短按KEY3启动。
3. 小车以任务4速度循迹到B点；测试点到达B时自动锁存`RES`，随后停车。
4. OLED进入`FINISH`后记录B点位置、`RES`和钢球最大偏移。

### 注意事项

- 当前软件停车目标与B点重合，没有额外的过B配置余量；
- 必须用实车确认车体测试点确实到达B，不能只看编码器理论1.50 m；
- 起步和停车阶段重点观察小球，必要时只调整加速度前馈，不同时改多个PID；
- 若起步补偿仍滞后，先只将`BALL FFLEAD 150`依次试到180、220 ms；不要同时增加`BALL FF`；
- 运行中按KEY3不会正常停车，异常情况使用KEY4急停。

## 8. 第5问操作：一圈并保持钢球中心

### 测试前

1. 选择`TASK 5`。
2. 点击“恢复中心零点”，确认零点为`0.00 cm`。
3. 等待钢球稳定在中心。
4. 将车辆测试点对准A点并确认循迹位置。

### 启动和结束

1. iPad开始录像。
2. 短按KEY3启动。
3. 小车自动循迹一圈；测试点越过A时锁存`RES`，随后继续短距离并平滑停车。
4. OLED进入`FINISH`后记录`RES`和整圈钢球最大偏移。

### 注意事项

- 评价重点是整圈保持误差，不仅是最终位置；
- 应分别观察直线、入弯、弯中、出弯和停车时的小球偏移；
- 返回A点的识别条件与任务2相同，起点摆放必须一致；
- Wi-Fi或iPad页面异常不应影响UART滚球控制，但当前浏览器录像可能中断。

## 9. 第6问操作：一圈并保持任意预设位置

### 测试前设置预设位置

1. 选择`TASK 6`，保持OLED为`READY`。
2. 将钢球放到裁判指定的预设位置，并用手安全保持稳定。
3. 等待至少5个连续有效检测帧。
4. 在8080页面点击“将当前钢球位置设为零点”。
5. 等待页面状态从`pending`变为`success`。
6. 核对页面显示的新零点数值与预设方向一致。
7. 松手后等待控制系统在该位置稳定，确认不会重新回到物理中心。

若设置失败，检查：

- 是否已完成有效标定；
- 当前是否检测到钢球；
- 最近5帧位置极差是否超过0.30 cm；
- 是否出现`stale/jump/miss/axis_filter`；
- 钢球是否被摆杆控制带动，无法保持静止。

### 启动和结束

1. 零点设置成功并稳定后，iPad开始录像。
2. 短按KEY3启动。
3. 小车自动循迹一圈并保持当前预设位置。
4. 测试点越过A时锁存`RES`，随后自动停车。
5. OLED进入`FINISH`后记录用时和相对预设点的最大误差。

### 注意事项

- 所有设零操作必须在KEY3启动之前完成；
- 运行中禁止再次点击设置零点或恢复中心；
- 可选零点只保存在当前MaixCAM进程，重启`main.py`或断电后恢复物理中心0 cm；
- Wi-Fi断开不会清除进程内零点，也不会停止UART控制；
- 下一轮若做任务2～5，必须点击“恢复中心零点”。

## 10. 异常处理

### 立即按KEY4的情况

- 小车冲出赛道或运动方向错误；
- 摆杆接近机械限位或钢球即将脱离；
- 电机堵转、异响、过热或线束卷入；
- OLED显示FAULT，或控制明显失控；
- Maix持续丢球且摆杆动作异常。

急停后：先松开KEY4，断开或移除危险源，排除故障，再重新长按KEY4约1秒复位。不得持续按住KEY4等待自动复位。

### Maix tracking=0

1. 检查钢球是否离开ROI、被遮挡或反光过强；
2. 检查相机和平台是否移动；
3. 检查标定轴线和框尺寸过滤是否误拒绝；
4. 检查AI帧率和相机读取失败计数；
5. tracking恢复前不得开始正式测试。

### iPad断线

- 实时滚球控制通过MaixCAM UART运行，不依赖iPad网页；
- 不要在车辆运行中重启MaixCAM或`main.py`；
- 当前录像保存在iPad浏览器内存中，页面断线、刷新或关闭可能导致本轮录像丢失；
- 当前版本没有车载TF卡断网续录，比赛前必须确认现有录像方式满足现场规则，否则需先补齐TF录像功能。

| 项目 | 记录内容 |

| 题号/轮次 | 例如T5-Run2 |

## 12. 比赛前必须冻结的事项

1. 用最终机械安装重新确认Maix五点标定最大误差不超过3 mm。
2. 确认`calibration_config.py`是最终标定，不再使用示例参数。
3. 当前`main.py`中`ENABLE_DISPLAY=False`，正式运行时保持关闭本机逐帧显示，以减少推理开销。
4. 用Keil ARMCLANG对最新MSPM0代码全量重编译并烧录。
5. 完成任务2～6至少各3次连续完整彩排。
6. 确认任务3的`+5/-5 cm`方向、任务6的任意零点方向和F32C机械方向一致。
7. 确认当前iPad录像方式满足评审要求；若要求无线断开后仍有车载完整录像，必须增加TF卡本地录像。
8. 保存一份最终代码、HEX、Maix应用目录和全部参数的只读备份。
